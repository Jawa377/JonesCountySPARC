# Project Brief

## Assignment
SPARC Textbook Studio: GCSU MMIS graduate course build for the Jones County
School System (JCSS) SPARC Academy. Source: `SPARC-Studio-Handout.pdf`
(concept brief, September 2026).

Timeline:
- **Fall 2026:** Scope and shadow. Pick the subject and grade, and load the CASE standards. Nothing ships.
- **Spring 2027:** Build and pilot. Teachers author one full unit in the tool and give weekly feedback.
- **Summer 2027:** Evaluate. Did it save time? Were the alignments right?

Scope: **one subject, one grade, one unit, done correctly.**

## Description
An AI-assisted authoring tool for SPARC Academy teachers. A teacher uploads
materials they already wrote (slides, labs, notes, vocab lists). The tool
drafts a textbook section, assignments, and a quiz, and every element is
tagged to a real Georgia standard. The teacher stays the author: everything
is editable, and nothing publishes on its own.

## Features
Phase 1 (in scope):
- [ ] **Units & materials:** create a unit (subject / grade / unit), upload PPTX, DOCX and PDF materials, and list them
- [ ] **Draft settings:** standards set, reading level (Lexile range), and voice ("match my materials")
- [ ] **Authoring Studio:** generate a draft textbook section, assignments and quiz from the unit's materials
- [ ] **Editing:** full edit control over the section, assignments and quiz, plus "Save to unit"
- [ ] **Standards Engine:** load Georgia CASE standards and tag each element with codes *retrieved* from that data
- [ ] **Coverage panel:** covered / partial / gap per standard in the unit, with actions ("generate" for a gap, "dismiss" when it's planned for a later section)
- [ ] **Traceability:** clicking a standard highlights the exact passage that covers it
- [ ] **Differentiated practice:** Support / Core / Extension items that share one standard code, plus a DOK-tagged exit check
- [ ] **Export to Google Docs** (TBD: may be deferred)
- [ ] **Time tracking:** the pilot measures authoring time with the tool vs. without it

Phase 2 (out of scope, needs JCSS legal and safety sign-off):
- [ ] Student Companion tutor, limited to the passage on screen and guarded by Bedrock Guardrails, with a teacher log

## Database Tables (final: `database/schema.sql` is the source of truth)
SQLite locally (`database/sparc.db`), MySQL (JawsDB) in production, chosen by `DATABASE_ENGINE`. Raw SQL, no ORM.
- `teachers`: teacher_id, name, email (unique)
- `units`: unit_id, teacher_id, subject, grade, unit_number, title, standards_set, lexile_min, lexile_max, voice
- `materials`: material_id, unit_id, filename, file_type (PPTX/DOCX/PDF), size_label. Upload records only.
- `standards`: standard_id, code, description, standards_set, source_url, framework (GSE / new ELA)
- `sections`: section_id, unit_id, section_number, title, learning_target, body_text, word_count, lexile, duration_minutes, status (draft/edited)
- `vocab_terms`: vocab_term_id, section_id, term, definition, sort_order
- `assignments`: assignment_id, section_id, level (support/core/extension), prompt_text
- `quiz_items`: quiz_item_id, section_id, dok_level, prompt_text
- `alignments`: alignment_id, unit_id, standard_id, element_type/element_id (NULL for a gap), coverage_status (covered/partial/gap), evidence_text (exact passage to highlight), evidence_note
- `coverage_dismissals`: dismissal_id, unit_id, standard_id, reason, dismissed_at

Seeded: Section 1 "Why Water Runs the Planet" (the page 2 studio draft) and Section 2 "Why the Coast Stays Mild" (the page 3 lesson, which holds the 3 assignments and the exit check). The lesson view is the same section record rendered with a different template, so there is no lessons table.

## Notes for Claude
- **Standards must never be generated by the model.** Codes come only from GaDOE CASE data (case.georgiastandards.org), loaded into an AWS Bedrock Knowledge Base, or into the `standards` table for local development. If a tag can't be traced to that data, don't show it.
- The coverage panel reports gaps honestly. Never pad coverage.
- AI output is always a first draft the teacher edits. Nothing auto-publishes.
- Handle Georgia's mixed standards frameworks: new ELA (2025–26), math updated earlier, science and social studies still on GSE.
- LLM provider: Amazon Bedrock (us-east-1). Credentials come only from env vars.
- **Current teacher:** Phase 1 has no login. A "current teacher" picker stores `teacher_id` in the Flask session, and every screen shows only that teacher's data. All reads go through one helper, `get_current_teacher()` in `app/functions.py`, so real auth later only replaces that helper. Confirmed: `teachers` table as drafted.
- Phase 1 touches **no student data** (FERPA). Don't add student tables or student logins.
- Copyright: a policy question for the professor, not a code decision. The code doesn't enforce it.
- Follow `CLAUDE_RULES.md`: functional programming only (no classes), plural blueprint files, singular routes, and modals for add/edit forms.
- **Pilot: 6th Grade Science, Unit 3, "Water in Earth's Systems"** (GSE Science, Grade 6, standards S6E3 / S6E4). Use it throughout for seed data, examples and defaults.
- **All Bedrock calls go through one module, `app/services/bedrock.py`, which has a single function.** For now it returns realistic sample data because there are no AWS credentials yet. Every screen and route is built for real. When AWS access arrives, only that module changes. Don't add `boto3` to `requirements.txt` until then.
